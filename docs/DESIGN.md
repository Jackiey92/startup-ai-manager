# SAM 资料柜与待办中心：前端设计说明

## 目标与边界

以现有原型的蓝紫主色、白色卡片、轻量边框和侧栏骨架为视觉基调，重构为 Flask/Jinja 多页界面。页面只呈现后端已提供的资料、事实和待办；不以占位数值填补未实现的经营分析能力。

## 信息层级

- **总览**：当前公司、已确认事实、待办摘要、真实资料分布和三个可行动入口。
- **待办中心**：冲突与重大事项分区；值、证据和系统建议先于操作按钮；处理后从真实接口刷新。
- **事实库**：当前有效事实的可筛选表格，来源 hash 始终可见。
- **文件柜**：按真实归类列出解析资料，内容证据/人工归类状态清楚区分。
- **对话**：只保留当前可用的 Agent 对话入口和真实返回消息。

## 交互与可访问性

- 所有操作目标最小高度 40px，主操作使用可辨识的主色和文字。
- 上传、待办写入和对话请求有 loading、成功或错误的真实反馈；不以定时器伪造结果。
- 颜色不作为唯一状态表达：标签同时含文字；表格使用语义化表头。
- 小屏时侧栏转为横向导航，表格容器可滚动，文件行和待办值块折为单列。

## 性能原则

不引入 CDN、构建链或第三方前端依赖；样式和脚本由 Flask 同源静态文件提供。页面服务端只聚合已有服务数据；长 hash 使用可换行等宽文本，避免撑破布局。
