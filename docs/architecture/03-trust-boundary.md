# 信任边界与外部数据清关

## 不是「完全隔离」，而是分区 + 单向阀门 + 入关检疫

产品价值在于「外部信号 × 内部上下文 × 行动」。外部数据若永远进不来，乘法做不成；若不加约束地进来，账本会被污染。因此借鉴供应链 / 海关模型：

```
外部数据源（不可信）
      │
      ▼
┌───────────────┐
│ 检疫区 / 保税区  │  外部身份永久保留，可被「引用」
└───────┬───────┘
        │ promotion（清关闸门）
        ▼
┌───────────────┐
│ 内部事实区（可信）│  验出处 · 打来源标 · 过校验 · 高风险人签字
└───────────────┘
```

## 三条硬规则

1. **存储分区**：外部区与内部区物理分开，schema 强制带 `origin_zone`，永不丢标；
2. **流向单向**：外部 → 内部只能经清关闸门；内部事实绝不允许被外部内容静默覆盖；
3. **引用 ≠ 入账**：
   - 「某新闻社说……」= 引用，外部身份不变；
   - 「因此本公司某事实应变更……」= 必须走入账流程；
   - 绝不允许一条新闻直接改写公司的账。

## 入关检查清单

- 原始出处是否可验证（URL / 刊物 / 机构 + 日期）；
- 是否打上永久来源标签（新闻 / 研报 / 论文 / 政策 / 前沿）；
- 类型、单位、时间口径是否归一；
- 与现有内部事实是否冲突；
- 高风险（影响股权、现金、合规）→ 人工签字。

## 工具接入的污染控制

- 连接器只读外部系统、默认写入检疫区；
- 凭证由网关代持，不进入模型上下文；
- 连接器抽象成可替换层，避免外部供应商锁定；
- 外部 API 失败 / 返回异常值时，不得回落为内部事实。

## 威胁模型关注点

- 外部内容诱导 Agent 做出错误内部变更（间接提示注入）→ 变更必须走闸门；
- 过期 / 被撤回的外部信息仍被当作当前结论 → as-of 与失效标记；
- 多源口径冲突被静默选取其一 → 一律标冲突、交人裁决。
